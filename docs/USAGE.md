# 历史使用说明（非发行版安装指南）

> 项目已停止维护。本页记录完整本机工程的历史功能；源码展示快照不含必要游戏资源和适配组件，不能直接照此启动。请先阅读 [源码分发说明](SOURCE_DISTRIBUTION.md) 与 [授权范围](legal/LICENSE_SCOPE.md)。

# AutoTaTa 0.2.36

统一主页：一键上阵、自动钓鱼、寻宝辅助、漂流大赛。字体 Chiron GoRound TC。

## 启动与打包

首次运行 `scripts/setup.bat` 安装 Python 3.12 依赖，然后运行 `scripts/start.bat`。
统一入口为 `main.py`；在项目根目录使用 `.venv\Scripts\python.exe -m fishing`、`-m treasure`、`-m rafting` 或 `-m lineup` 独立启动对应功能，也可使用 `scripts/` 中的相应批处理。

直接运行 `scripts/build.bat`（或 `scripts/build.bat all`），只构建和发布 **AutoTaTa 统一程序**。钓鱼、寻宝、漂流使用同一个 Python、Qt、图像识别和 OCR 运行环境；依赖不会按功能复制。主页按需加载功能。

可执行文件：`dist/all/AutoTaTa.exe`。正式发布包：`releases/<版本>/all/AutoTaTa-<版本>-windows-x64.zip`，只含统一程序和说明，不打入独立版本、测试截图或构建缓存。

不再生成各功能独立发布包，源码的独立启动入口继续保留。每次成功生成 ZIP 后，按版本号保留最近 **3** 个已发布版本，自动清理更旧的 release 包、对应暂存目录及保留版本中的独立包；构建或压缩失败时不清理旧版本，也不会覆盖上一份完整 ZIP。

## 当前可用

- 一键上阵导入图片后自动开始识别并尝试部署，请先选好设备并停留在游戏上阵界面；已确认格子先行处理，不确定格子保留问号，可随时停止并修正。

- 主页四个入口均可使用；一键上阵采用入口对应的绿色配色。
- 四个功能的下拉菜单与输入框居中同宽，右下角缩放图标统一；弹窗使用独立系统窗口，点击外部或完成操作后关闭。
- 原有钓鱼逻辑迁移，增大返回按钮，居中标题。运行或关机倒计时期间需要先停止/取消再返回，防止隐藏自动化状态。主页不响应钓鱼快捷键。
- 寻宝采用与 Figma 同步的 800 宽左右分栏布局及营地配色；识别为主入口，按钮、卡片与钓鱼共用组件。
- 寻宝界面自动按完整内容适配屏幕，右下角等比拖拽缩放整个界面；弹窗随界面等比缩放，宝物列表至少容纳五行。
- 寻宝 1–24 关预设，修改棋盘、成本、宝物尺寸/数量，标记空格或宝物，恢复未挖、撤销、清空。
- 本地矩形放置概率，完整枚举超过上限时改为拒绝采样，明确标注抽样；不将截断枚举伪装成准确概率。
- 预计剩余消耗：在有限布局样本上模拟优先选择高命中概率格，近似值，非最优策略保证。随机不重复挖掘期望值同时作为参考。

## 一键上阵（第一版）

1. 点击图片框选图、拖入图片，或在程序前台按 Ctrl+V 粘贴截图。图片框内会显示识别进度。
2. 塔塔图鉴网格和卡片阵容可自动定位；没有完整格子边界的游戏截图，使用“框选阵型”框住自己的完整场地，排除上方敌方队伍和下方按钮。支持 5×5 和 3×4，敌人在上方。5×5 截图必须保留空行；只截三四行不能通过框选拉伸补齐，程序会提示重新截图。
3. 检查预览；点击任意格子搜索并更正塔塔、添加塔塔或设为空位。问号表示识别不确定。
4. 在游戏中进入上阵界面，点击“一键上阵”（Home）。先检查已上场塔塔，保留匹配塔塔并拖到目标格子，点击收回不匹配塔塔；位置互换时借用空格。再按属性逐只查找库存，找到后立即拖拽上阵，不预先扫描完整库存、不点击全部下阵。筛选标记无法确认时退回全部库存，以塔塔图像为准。每条进化链在库存中只有一个阶段，找到同链塔塔后直接使用，不继续翻页找图片阶段；已上场的同链塔塔不重复查找。每次操作核对数量和位置身份；场上多帧仍无法确认的塔塔点击下阵，确认人数减少和原格空出后重新规划并继续。阵容图片中的问号仍可手动修正，库存缺失位置允许部分完成。PgDown 可停止。

- 资料库包含从 [TataDex](https://tatadex.org/zh/tatari/) 公开页面取得的 248 张透明 PNG、67 条进化链及元素、定位、阶段；记录来源和校验值。
- 使用库存中可以确认的同进化链阶段，不选择其他进化链凑数。
- 读取上阵数量、上限和下阵按钮，按灰度棋盘交替结构定位场地。角色轮廓不参与颜色判格。
- 不确定、未找到、超过上限的格子会跳过，先部署已确认部分。MuMu 前台覆盖层标出待处理位置，软件预览也显示原因；通用 ADB 未关联 Windows 窗口时只在软件内标注。
- 每次拖拽前重新核对库存、场地和数量；拖拽后确认数量、目标格子及塔塔身份。MuMu 后台模式使用 SDK 截图与绑定同一显示区的连续原生触摸：按住立即移动，先向上拖出列表，再移动到指定格子；不点击库存卡片上阵。没有等级文字的卡片也正常处理。
- 两行库存共同校准卡片列位置；翻页在卡片行内水平滑动，数量变化则停止。动态姿态允许多帧确认，场地位置由灰度棋盘与独立控件共同核对。
- 2026-10-15 使用用户提供的 15 只阵容图在当前 MuMu 实测完成 15/15，包含收回、移位、无等级字样卡片、横向翻页及同链替代。小图、动态姿态、徽章遮挡仍可能需要手动更正；不同样式识别不准时可框选场地和逐格修正。库存扫描限定 40 页，无法确认则停止，不重复拖拽、不点击“开始战斗”。
- Figma 页面宽 615，包含待开始、识别中及手动修正弹窗，保留 Windows 原生阴影。
- 阵容图片标题右侧的“截图”按钮可启动 Windows 区域截图；框选后回到程序按 Ctrl+V 导入，也可点击输入框选择图片。

## 自动寻宝辅助

进入 MuMu 的营地寻宝棋盘，在软件内选择设备并点击“自动识别”，再次点击“停止识别”可关闭。程序只读截图，不自动挖格、不消耗镐子。

- 读取 MuMu SDK 原始画面，连续稳定帧确认后持续更新，直到手动关闭自动识别。棋盘变化时先隐藏旧覆盖层，识别新结果后自动恢复；连接中断会重试。覆盖层仅在 MuMu 前台显示。
- 已观察、确定或轮廓推断的宝物格显示宝箱；推断标记可手动校正，不作为已挖证据。推荐优先探索尚未定位的宝物，不提高原始概率。
- 定位棋盘、读取关卡与实际每格消耗、识别已挖空地与宝物格，提取上方宝物剪影。
- 托盘宝物与参考预设不一致时优先使用现场剪影估算尺寸，并提示核对；关卡不清楚也可按自定义配置工作。
- 结合已露出宝物的轮廓比较旋转候选，联合排除重叠布局。确认宝物格显示宝箱且不显示百分比；未确认推断不会冒充已挖宝物。
- MuMu 在前台时显示可穿透鼠标的概率覆盖层；其他窗口前台、最小化、画面失效时自动隐藏。后台识别继续，不切换输入通道。
- 点击格子，在下方弹出菜单标为空地、宝物或恢复未挖。宝物列表可加减数量，点击尺寸修改，弹窗输入宽、高、数量添加；校验总占格，支持撤销。
- 预计消耗为当前识别与有限样本下的策略估算，不能保证实际最少消耗；剪影尺寸不确定时先核对“宝藏配置”。

参考网站与本机实际第一关配置存在差异，不能把 1–24 关预设当成游戏的固定真值。多实例无法唯一确定时会提示，不会选择不明目标。

预设事实来源：https://tatadex.org/zh/events/treasure-hunt/ ，2026-10-09 逐关核对。计算器为本地独立实现，不宣称与网站完整算法一致。
钓鱼功能、素材、设置与设计原稿已迁入本项目，旧 tata-autofish 目录清空。构建缓存和运行日志不属于源文件，也不作为分发内容。

## 文件组织

- fishing/：完整钓鱼功能；treasure/：寻宝辅助；autotata/：统一主页。
- assets/：程序运行素材；design/：Figma 索引、维护说明及分层图标原稿。
- tools/font-source/：完整 Chiron GoRound TC 字体源，供后续字库扩充。
- docs/history/：旧钓鱼项目的说明和发布记录。
- .venv/：本项目独立运行环境；build/：可重建缓存；dist/：当前可执行程序。

主页按需加载功能，无启动动画；项目根目录 AutoTaTa.lnk 指向 dist/all/AutoTaTa.exe。


## 漂流大赛

主页进入“漂流大赛”，或通过 `scripts/start-rafting.bat` 独立启动。进入漂流大赛活动后选择设备与操作模式，可从转盘、漂流动画、三选一、奖励、卡包、扭蛋、领取确认及已识别的规则／排行页面接管。规则／排行须有活动依据与可见关闭按钮；不使用暗下去的游戏退出按钮。Home 开始，PgDown 停止。

期望倍率为 1/2/3/5/10/20/50/100/150，支持运行中调整，下一轮转盘前应用；受船数量限制时根据游戏的“所有奖励最大”提示或完整倍率循环使用可用上限。转盘操作仅提交一次，等待转盘旋转、船的明显左右位移及奖励处理结束，再确认结算。角色动画、小幅上下/左右晃动不重新计时；倍率重绘不计作漂流轮次。程序与 Figma 的漂流页均以 615 宽设计，窗口自动按屏幕空间缩放。

启动按钮上方有横向六个抠图奖励图标，使用统一纯色底、居中显示，左右拖拽排序，越靠左越优先；“恢复推荐排序”恢复默认顺序。当前默认顺序为心愿盒、弹珠、扭蛋、船、饭盒、糖果。三选一仅匹配中间三张卡片并点击对应的“选择”，不会读取卡片上方的干扰说明。未识别的奖励、点击未响应或画面停止更新时不会继续盲点。

漂流功能随 `scripts/build.bat` 生成的统一包发布，包内排除 assets/fixtures 测试素材。当前已根据用户截图、46 秒转盘录屏及 79.5 秒奖励录屏离线校准，另有明确标注的规则／排行、奖励续领和购船合成布局检查。活动子页、购船窗口及长时间连续运行仍需实际游戏验证。

漂流预算在“期望倍率”区域内，位于“当前倍率／剩余船”上方，以本次提交用船计数，0 表示不限；剩余预算不足期望倍率时下调倍率，等本轮奖励处理完后停止。接管中的原有轮次和免费转盘不计入预算。最下方的完成后关机与强制关机开关复用钓鱼控件和关机方式。完成后关机默认关闭，每次启动需手动开启；预算正常完成时倒计时 15 秒，可取消。强制关机会关闭未保存的应用。手动停止、退出或识别/连接错误不会触发关机。卡包点击“开心收下”，优先选择后的领取页点击“确定”。

检测到漂流艇购买文字，或购买窗口内的船图标时立即停止，不点击购买、不将弹窗推断为库存数字归零。仅显示购船窗口不足以证明船已耗尽，因此不当作预算正常完成。规则里介绍如何购买船不算购买窗口；“确定”和通用绿色领取按钮在新的页面分类完成前等待，防止在已有奖励上下文中误点购买。未知页面或没有关闭按钮的子页保留等待／停止处理。

活动补给礼包页采用钓鱼与漂流共用的判断：先识别重复的双列、多行礼包按钮布局，再核对黄色按钮内的货币符号与金额、绿色按钮内的“免费”；不依赖按钮固定坐标、价格、礼包顺序或恰好六个按钮。全免费或全付费布局还需确认礼包标题。识别到此页后停止，不点击免费、购买或关闭按钮，不额外记预算，也不触发完成后关机；手动进入礼包页也可能出现相同布局，因此不据此把库存显示改成0。新的活动可复用同一判断；寻宝辅助本身只读画面、不自动挖掘。
